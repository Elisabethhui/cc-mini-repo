# Watchdog Policy

## 文档目的
本文件定义 Watchdog 的职责边界，确保它只负责低风险、低成本的变化监听与状态维护，而不越权替代 digest、reconcile 或人工判断。

## Watchdog 管什么
1. 监听文件变化。
2. 发现受影响的 Wiki 页面或实体页。
3. 对受影响页面标记 `stale` 或待处理状态。
4. 维护待处理队列，例如：
   - `digest_queue`
   - `reconcile_queue`
5. 记录必要的变更日志。

## Watchdog 不管什么
1. 不自动执行高成本大规模 digest。
2. 不静默覆盖已有 digested 页面。
3. 不自动生成最终 reconcile 结论。
4. 不直接修改业务代码。
5. 不替代人工审批或高风险写入。
6. 不负责包揽所有状态转换来源。

## 触发条件（初版）
1. 代码文件发生变化。
2. 文档源文件发生变化。
3. 被引用的关键页面失效。
4. 规则页变化导致已有页面规范可能过期。

## 与其他触发源的关系（新增）
### 本步已拍板
页面状态变化可以来自三类来源：
1. 时间触发
2. Git / 文件变化触发
3. 人工命令触发

### Watchdog 在三类触发中的位置
- Watchdog 主要负责 **Git / 文件变化相关的低成本监听**。
- 时间触发可以由单独的计划任务、巡检任务或后续运维机制承担。
- 人工命令触发由 `/digest`、`/reconcile`、归档命令或人工审核承担。

> 结论：状态转换有三类来源，不等于都由 Watchdog 负责执行。

## 标记规则（初版）
发生影响时，优先做以下动作：
1. 标记相关页面为 `stale`。
2. 写入受影响 symbol 或路径。
3. 放入待 digest 或待 reconcile 队列。
4. 在 log 中追加记录。

## 风险控制规则
1. Watchdog 只能做便宜、保守、可回滚的动作。
2. 当无法确定影响范围时，宁可标记待人工处理，也不要自动扩写摘要。
3. Watchdog 记录的变化应可追溯到源文件或事件时间。

## 验收口径
一个合格的 Watchdog 行为应满足：
1. 能发现变化。
2. 能把页面从“可能可信”调整为“需复查”。
3. 不会偷偷替用户做高风险推断或覆盖。
