# Conflict Policy

## 文档目的
本文件定义当 Wiki 页面、原始代码、历史摘要、归档内容之间出现不一致时，如何判断优先级、如何标记冲突，以及哪些操作必须禁止。

## 管理对象
- Raw Sources
- 结构扫描生成的页面
- digest 页面
- archive 页面
- 历史设计与历史结论

## 不管理对象
- 不负责具体 reconcile 算法实现。
- 不规定 Git 合并冲突的底层处理方法。
- 不替代人工最终裁决。

## 基本原则
1. Raw Sources 是事实基线，不可被 Wiki 静默覆盖。
2. Wiki 是解释层，不是事实替代层。
3. 新内容与旧内容冲突时，先标记再处理，禁止直接覆盖。
4. 高置信度页面与历史页面冲突时，必须保留来源痕迹。

## 优先级原则（初版）
通常优先级建议为：
1. 最新且可验证的 Raw Sources
2. 与当前源一致的 digested 页面
3. 部分 digest 页面
4. 历史页面 / archive 页面
5. 无明确来源的口头结论

## 冲突类型（初版）
1. 源代码已变更，但页面仍描述旧逻辑。
2. 两个摘要对同一 symbol 给出不同结论。
3. 历史方案与现行实现不一致。
4. 新 digest 与旧 digest 的风险判断相冲突。

## 必须执行的动作
1. 对受影响页面标记 `stale`、`historical` 或 `superseded`。
2. 在需要时写入冲突说明或待 reconcile 队列。
3. 保留旧页面的来源和时间信息，避免语义失真。

## 禁止动作
1. 禁止静默删除旧结论。
2. 禁止把历史页伪装成当前可信页。
3. 禁止在未检查来源的情况下强行合并结论。
4. 禁止用“模型猜测”替代缺失事实。

## 裁决结果（初版）
冲突处理后，页面通常进入以下之一：
- 维持当前页但标记 `stale`
- 新建 superseding 页面
- 归档为 `historical`
- 进入 reconcile 队列等待后续处理
